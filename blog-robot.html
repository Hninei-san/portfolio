something I love: robots

How I learn stuff I have no clue about (by building a robot) 🤖

Ok so I wanted to build a UAV-UGV robot (one that flies and drives) and had no idea how. This thread is less about robots and more about how I got unstuck, because that part works for pretty much anything new.

  1. 1

    Not knowing anything

    I wanted to build a UAV-UGV robot. I didn't know what parts I needed or what to even google first. Honestly the blank-page feeling was the worst part.

  2. 2

    Shrink the big scary question

    "Build a robot" is way too vague to start on. So I did a sticky note brain dump and wrote down every question in my head, even the dumb ones, before trying to answer any of them.

    what should it even do?? how does it move? what do I buy lol how does it know what's in front of it what's the "brain"? how does my code make motors go is this too hard

    Once they were all out on the table, none of them looked as scary as "build a robot" did.

  3. 3

    Make a materials list

    Next I turned the sticky notes into a list: what I needed to get and what I needed to learn, split into hardware, software, and integration. Then I only had to learn the next thing, not all of robotics.

    Hardware

    Materials

    • motors + wheels
    • motor driver
    • battery / power
    • a sensor
    • a board to run the code

    Need to learn

    • how motors work
    • wiring + power basics
    • how a sensor gives you numbers
    Software

    Materials

    • a laptop + code editor
    • ROS

    Need to learn

    • enough programming to send commands
    • how to read sensor values in code
    • what a ROS node is
    Integration

    Materials

    • cables to connect it all
    • patience

    Need to learn

    • how my software talks to the hardware
    • testing one piece at a time
    • making sensor input change what the motors do

    Hardware and software are pretty separate. Integration is where they have to work together, and it's where most of my problems showed up.

  4. 4

    Go in order

    I started by researching and reverse engineering, since I had no clue how a UAV-UGV robot even works. This is the order I took it in, and I didn't move on until each part made sense. Tick them off as you go.

    1. 1

      Research + reverse engineer

    2. 2

      Learn UGV and UAV

    3. 3

      Do the calculations

    4. 4

      Prepare materials

    5. 5

      Software stack

  5. !

    It will break (a lot)

    Robot doesn't move. Cool, now what? It could be a bunch of things, so I went through them one by one.

    My debugging checklist

    Annoying, but honestly debugging taught me more than anything else did.

  6. 6

    AI as a study buddy

    • I used ChatGPT when I needed a concept explained in plain English.
    • If it still didn't click, I'd ask Claude or Perplexity, since a different explanation sometimes makes it make sense.
    • I also asked AI to help me debug when I was stuck.
    • But I double check the important stuff. AI gets things wrong sometimes.
  7. 7

    Doing beats reading

    I could read 20 ROS tutorials and still not get it. Then I got one ROS node to talk to another and it finally made sense.

  8. 8

    What I took from it

    You don't have to understand everything before you start. Take the huge scary thing, chop it up, and solve one tiny piece at a time.

Go try something you know nothing about. Start with one small question.
