LEARNING LOG

How I learn stuff I have no clue about

I wanted to build a UAV-UGV robot and had no idea how. This is less about robots and more about how I got unstuck — because that part works for pretty much anything new.

ROUTE MAP

The Learning Path

01
START

Not knowing anything

I wanted to build a UAV-UGV robot. I didn't know what parts I needed or what to even google first. The blank-page feeling was the worst part.

02
BRAIN DUMP

Shrink the big scary question

"Build a robot" is too vague to start. So I did a brain dump — every question, even the dumb ones.

what should it even do?? how does it move? what do I buy lol how does it know what's in front of it what's the "brain"? how does my code make motors go is this too hard

Once they were all out, none of them looked as scary.

04
EXECUTE

Go in order

I started by researching and reverse engineering. I didn't move on until each step made sense.

  1. 1

    Research + reverse engineer

  2. 2

    Learn UGV and UAV

  3. 3

    Do the calculations

  4. 4

    Prepare materials

  5. 5

    Software stack

03
ORGANIZE

Make a materials list

Turned sticky notes into a structured list: hardware, software, integration.

Hardware

materials

  • motors + wheels
  • motor driver
  • battery / power
  • a sensor
  • a board to run code

learn

  • how motors work
  • wiring + power basics
  • how a sensor gives numbers
Software

materials

  • a laptop + editor
  • ROS

learn

  • programming to send commands
  • reading sensor values
  • what a ROS node is
Integration

materials

  • cables to connect it all
  • patience

learn

  • software ↔ hardware
  • testing one piece at a time

Integration is where most problems showed up.

!!
REALITY CHECK

It will break (a lot)

Robot doesn't move. Cool, now what? I went through issues one by one.

> open debug.log

Debugging taught me more than anything else did.

06
TOOLS

AI as a study buddy

  • Used ChatGPT when I needed a concept in plain English.
  • If it didn't click, I'd try Claude or Perplexity for a different angle.
  • Also asked AI to help debug when I was stuck.
  • But I double check the important stuff. AI gets things wrong.
★
DESTINATION

What I took from it

You don't have to understand everything before you start. Take the huge scary thing, chop it up, and solve one tiny piece at a time.

07
HANDS ON

Doing beats reading

I could read 20 ROS tutorials and still not get it. Then I got one ROS node to talk to another and it finally made sense.

> Go try something you know nothing about. Start with one small question._
